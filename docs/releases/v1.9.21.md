# A11y Notebook v1.9.21 — What's new and what changed

Everything in this release was merged since v1.9.20 (November 19, 2026).
It brings the OCR button and PDF bookmarks as new features, plus the
remaining fixes from the v1.9.20 retest: the title bar, Continuous view,
PDF notes, bookmark jumps and shortcuts, the context menu, and the
search reminder time.

## What's new

### OCR this file, for open ePubs and PDFs

- A new "OCR this file" button sits in the reader for open ePubs and
  PDFs. It recognizes text on-device only (Tesseract, built into the
  app — nothing leaves the computer) and only for pages or sections
  with no extractable text, so a book that already has real text is
  untouched.
- The recognized text shows temporarily in the reader. Save it into
  the file with Ctrl+S or the "Save into file" button: managed files
  update in place, and an Alius saves a copy in the library without
  touching the original. PDFs get a hidden text layer, so the
  recognized text is searchable and selectable.
- Progress shows while it runs and you can cancel; the language is
  asked each time. English is built in, and other languages download
  once and then work offline.

### PDF bookmarks

- You can now bookmark a PDF at the page and the spot on it, just
  like a position bookmark in a note. The bookmark shows under the
  same Bookmarks heading, scoped to the open file, and setting one
  asks for a name with "Page N" filled in.
- Activating a PDF bookmark opens its PDF if it is closed and jumps
  to the page and spot, in Paginated and Continuous view. PDF
  bookmarks persist across sessions and can be removed like note
  bookmarks. Moving or renaming a PDF carries its bookmarks along.

### Continuous view for PDFs

- A toggle in the PDF Page Navigation section, before the Previous
  and Next Page buttons, switches between "Paginated view" and
  "Continuous view". Continuous view shows the whole PDF as one
  continuous page, so you no longer have to move page by page to
  read through it.

## What changed

### ePub sections show their real chapter titles

- A section heading used to show a long code such as
  "c83aa0f9-11cc-48f8-ad60-b5084ec13b43" — a blob-URL identifier
  leaking into the label. Sections now show the table-of-contents
  title, the document title, or the file name, and never the blob
  URL.

### ePub books open on the first section with text

- A book used to open on its cover, which genuinely has no text, so
  the first thing heard was "No extractable text was found in this
  section." The reader now opens on the first table-of-contents
  entry with text, or the first section with text. A saved reading
  position still wins, and the cover stays reachable with Previous
  section.

### Bookmark jumps move focus in Markdown notes

- Jumping to a bookmark in a Markdown note now moves the programmatic
  keyboard focus to the bookmarked location, using the same method as
  jumping to a Find match. Headings that used to fail silently —
  image-only headings, footnote headings such as "Usage[^1]", and
  headings with entities such as "&copy;" — now land correctly, and
  a saved reading position no longer yanks focus back after a jump.

### The title bar names the open notebook

- In Notes and Files, Tasks, Cognitive Tools, Calendar, and Reminders
  views, the title bar now reads "[currentView] |
  [CurrentlyOpenNotebookName] | A11y Notebook", for example "Notes &
  Files | Portland Research | A11y Notebook". Libraries, Notebooks,
  and Contents views stay as they are.

### The context menu is the same however you open it

- From the Notes and Files grid, Shift+F10 and the Applications key
  used to open different menus: the Applications key opened the
  general Application menu while Shift+F10 opened the item menu.
  Both keys now open the same item menu.

### PDF notes have a heading and in-text buttons

- With one or more annotations in an open PDF, "Saved PDF notes…"
  is now a semantic heading, so it is easy to locate and navigate
  to. A "Note1", "Note2", and so on button now sits in the PDF text
  at each annotation, and activating one jumps directly to that note
  in the list.

### Search results show reminder times in local time

- A reminder set for 11/22/2026, 10:40 AM used to display as
  "11/22/2026, 6:40 PM" in search results — the time was shown in
  UTC instead of local time. It now shows the correct local time.

### Bookmarks are scoped to the open file

- With a note open, only that note's bookmarks show under the
  Bookmarks heading. With no note open, the library's bookmarks
  show, so the list is still the way to jump into a closed note at
  its bookmark. With no note open, setting a bookmark now announces
  "Open a note to set a bookmark."

### Bookmark shortcuts: B sets, H sets, J jumps

- Ctrl+Alt+B sets a position bookmark, Ctrl+Alt+H sets a heading
  bookmark, and Ctrl+Alt+J jumps to the next bookmark, wrapping
  back to the first when you are past the last — in notes and in
  PDFs. In a PDF, B bookmarks the current page and spot, and H
  announces that heading bookmarks are for notes. Heading bookmarks
  can still be set from the Tools menu or the command palette.

### Moving a notebook no longer hides its confirmation

- Moving a notebook out to the Library root while one of its notes
  was open used to end on a spurious "Could not load annotations."
  instead of the move confirmation. Open-note paths are now remapped
  before the move is applied, so the confirmation shows.

### Other changes

- The automated end-to-end tests now number 95 (new scenarios for
  the ePub initial section, OCR, Continuous view, PDF bookmarks, and
  the bookmark shortcuts), and still run as a blocking check in CI
  and as part of the release workflow.

## Known limitations

- Mac releases ship unsigned (right-click, then Open, to install; no
  Mac auto-update while unsigned).
- The automated end-to-end tests cannot check screen-reader
  announcements or the virtual-cursor position; manual screen-reader
  testing remains the only check for those.
- XFA forms show an honest notice rather than fillable fields:
  pdf.js exposes no XFA fields through its field APIs.
- PDF notes cannot load for a password-protected PDF. Form filling
  itself works on a password-protected PDF, and the filled values
  stay saved in the app — but a filled file cannot be created from
  it, so "Download filled PDF" is unavailable for password-protected
  PDFs.
- Permission-protected PDFs import as read-only: notes and a filled
  file are unavailable, though form filling works in the app and the
  filled values stay saved.
- Alius targets live outside the library, so they are not included
  in a library backup and their contents are not indexed by search:
  only the Alius record's name appears in search results, and
  restoring a backup can produce broken Alius records.
- Bookmark jumps still mismatch on Markdown setext headings and
  blockquoted headings, which the source heading scan cannot see.
- PDF, ePub, and DOCX previews keep their own search boxes; the Find
  match list does not cover them.
- Very large spreadsheets (thousands of rows) may be slow to display;
  the reader caps workbooks at 10,000 rows, 256 columns, and 500,000
  cells, and slide decks at 500 slides. Spreadsheet save preserves the
  file's styles, images, and other parts; ODS cells keep their original
  cell styles. `.xls` reading uses the SheetJS community edition
  (Apache-2.0) — the one format without an in-house reader.
- A permanent delete of a note containing tasks still shows the app's
  existing native permanent-delete confirmation after the task guard.
- The Citations dialog's "Switch to edit mode" button deliberately
  does not move focus while the dialog is open: focus must stay in
  the dialog so a citation can be inserted.
- F3 and Shift+F3 remain intercepted by JAWS in browse mode; use the
  Find match list, or Insert+3 (JAWS pass-through) then F3, to repeat
  a search.
- Items still awaiting a retest verdict: move-migration link survival,
  import formats, ePub chapter resume, PDF navigation and annotation
  persistence, audio features (real microphone, model download,
  dictation accuracy, playback with a screen reader, mp3/wav import),
  and the library picker.

## Mac install note

Mac builds are not signed yet. To install, right-click (or Control-click) the .dmg file, then choose Open. In-app updates do not work on Mac while the builds are unsigned — install each new version manually from the releases page.
