# A11y Notebook v1.9.20 — What's new and what changed

Everything in this release was merged since v1.9.19 (November 18, 2026).
It is a fixes release: the four remaining items from the v1.9.19 retest
and the autosave race that could show a spurious "Note changed on disk"
message after a manual save. No new features, and nothing in it changes
how existing features work except where noted.

## What's new

### Protected PDFs can be imported as read-only

- A protected PDF used to be refused outright with "Protected PDFs
  cannot be imported as managed documents." It now imports as a
  read-only managed document: the reader shows a notice that notes
  and a filled file are unavailable, and Download filled PDF and Save
  filled copy are disabled. Form filling still works in the app, and
  the filled values stay saved.
- Password-protected PDFs already imported and still do: the reader
  asks for the password once per session, then reads.

### Pictures can be pasted into an open HTML note

- Pasting a picture into an open HTML note used to paste nothing.
  HTML notes open in plain source mode by default, and the source
  textarea only stored pictures for Markdown notes. It now stores
  the picture beside the note and inserts an inline image with its
  description at the caret, the same way Markdown notes already did.
- The Wikipedia alt-text case in Notes and Files already kept the
  description and needed no change.

### Nothing opens automatically after a paste or a Web capture

- Pasting structured content into Notes and Files no longer opens
  the new note on its own — it waits in the grid until you open it.
  The same goes for Web capture: a captured page now lands in Notes
  and Files instead of opening as a note.
- Pasting now works from the navigation-pane grid too. With a note
  open, the Notes and Files grid lives in the navigation pane, and
  Ctrl+V reached no paste handler at all there. It now pastes into
  the open notebook without asking which notebook — the grid already
  shows it — and without opening the new note.
- The paste dialog's promise is reworded to say the note is kept for
  you to open when ready.

## What changed

### Saving by hand no longer triggers a spurious "Note changed on disk"

- The 900 ms autosave could fire during a manual Ctrl+S with the
  pre-save baseline, and the save was rejected as "Note changed on
  disk". The manual save now clears the pending autosave timer
  first, so the save goes through cleanly.

### Other changes

- The automated end-to-end tests now number 75 (6 new scenarios:
  protected-PDF import, the autosave race, navigation-pane paste,
  and the HTML-note picture paste), and still run as a blocking
  check in CI and as part of the release workflow.

## Known limitations

- Mac releases ship unsigned (right-click, then Open, to install; no
  Mac auto-update while unsigned).
- The automated end-to-end tests cannot check screen-reader
  announcements or the virtual-cursor position; manual screen-reader
  testing remains the only check for those.
- XFA forms show an honest notice rather than fillable fields:
  pdf.js exposes no XFA fields through its field APIs.
- PDF notes cannot load for a password-protected PDF. Form filling
  itself works on a password-protected PDF, and the filled values
  stay saved in the app — but a filled file cannot be created from
  it, so "Download filled PDF" is unavailable for password-protected
  PDFs.
- Permission-protected PDFs import as read-only: notes and a filled
  file are unavailable, though form filling works in the app and the
  filled values stay saved.
- Alius targets live outside the library, so they are not included
  in a library backup and their contents are not indexed by search:
  only the Alius record's name appears in search results, and
  restoring a backup can produce broken Alius records.
- Bookmark jumps still mismatch on Markdown headings containing raw
  HTML.
- PDF, ePub, and DOCX previews keep their own search boxes; the Find
  match list does not cover them.
- Very large spreadsheets (thousands of rows) may be slow to display;
  the reader caps workbooks at 10,000 rows, 256 columns, and 500,000
  cells, and slide decks at 500 slides. Spreadsheet save preserves the
  file's styles, images, and other parts; ODS cells keep their original
  cell styles. `.xls` reading uses the SheetJS community edition
  (Apache-2.0) — the one format without an in-house reader.
- A permanent delete of a note containing tasks still shows the app's
  existing native permanent-delete confirmation after the task guard.
- The Citations dialog's "Switch to edit mode" button deliberately
  does not move focus while the dialog is open: focus must stay in
  the dialog so a citation can be inserted.
- F3 and Shift+F3 remain intercepted by JAWS in browse mode; use the
  Find match list, or Insert+3 (JAWS pass-through) then F3, to repeat
  a search.
- Items still awaiting a retest verdict: move-migration link survival,
  import formats, ePub chapter resume, PDF navigation and annotation
  persistence, audio features (real microphone, model download,
  dictation accuracy, playback with a screen reader, mp3/wav import),
  and the library picker.

## Mac install note

Mac builds are not signed yet. To install, right-click (or Control-click) the .dmg file, then choose Open. In-app updates do not work on Mac while the builds are unsigned — install each new version manually from the releases page.
