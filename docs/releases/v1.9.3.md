# A11y Notebook v1.9.3 — What's new and what changed

Everything in this release was merged since v1.9.2 (October 27, 2026).
It ships Windows and Mac together; Mac builds are unsigned first.

## What's new

- **Reading mode, directly.** Ctrl+R enables reading mode in notes and
  files without toggling. Ctrl+E still toggles between editing and
  reading mode.
- **Find across the open document.** Ctrl+F searches the active
  document, not just notes: notes via a Find dialog in both reading
  and editing mode (with Find next, Find previous, and an optional
  Match case); PDF, ePub, and DOCX previews by moving focus to the
  reader's own search box; text and CSV attachments via the Find
  dialog on the rendered preview; HTML attachments by match count.
  After the dialog closes, F3 finds the next match and Shift+F3 the
  previous match of the last search. F3 with no previous search
  reports that instead of searching.
- **Libraries view grid.** The Libraries view now shows every library
  the app knows about (the open library plus recent ones,
  deduplicated) in the same accessible grid the notebooks and Notes &
  Files views use: Name and Path columns, sortable headers, arrow-key
  navigation, Enter to open. The open library's row is marked
  selected, and Enter on it does nothing.
- **Name the pasted notebook.** When a folder pasted into the
  Libraries view has loose files and you choose to put them all in
  one new notebook, the dialog now offers a "New notebook name"
  textbox, prefilled with "Pasted files" and focused so you can type
  right away. Leaving it blank keeps "Pasted files", illegal
  characters become underscores, and a name clash still gets a -2
  suffix. The per-file choice is unchanged.
- **Guided tour.** A 5-page guided tour auto-shows once per install
  or update, with a "Don't show this again" checkbox and a Help-menu
  entry to reopen it.

## What changed

- **The app opens with nothing open.** The Welcome tab is removed;
  the landing view is Notes & Files. With no tab or session
  persistence, the app already opened with no documents, so removing
  Welcome covers opening with nothing open, with no separate setting.
- **New note on a fresh open asks for a notebook first.** From the
  old Welcome tab, File → New note created the note at the library
  root. From Notes & Files as the landing view, it now asks you to
  select a notebook before creating a note.
- **Libraries grid drops the last-opened date.** The old recent list
  showed when each library was last opened; the grid shows Name and
  Path instead, so same-named libraries in different folders are
  still distinguishable.

## Fixes in this release

- **Settings files with a shortcut conflict now load.** When an
  explicit shortcut binding collides with a registry default, the
  explicit binding wins and the default becomes unbound, instead of
  the whole file failing its validity check. Concretely: a settings
  file that binds Bookmark selected note to Ctrl+Shift+B now loads
  with Bookmark keeping Ctrl+Shift+B and Back up library unbound,
  and the rest of the settings load with it. Saves, which the
  no-clobber guard refused while settings failed to load, unblock on
  the first load of this release, and the file heals itself on the
  next save.

## Known limitations

- **Unsigned builds.** Windows may show SmartScreen warnings and macOS
  may show Gatekeeper warnings (install via right-click → Open). There
  is no code-signing certificate yet, and no Apple Developer account for
  Mac signing and notarization.
- **Mac icon.** The Mac icon was generated from the Windows icon's
  256px image (the largest source available), so large icons render
  soft until a higher-resolution source exists.
- **Mac in-app updates do not run while unsigned.** Mac users download
  new versions from the release page.
- **Background reminders are Windows-only.** The setting is labeled as
  such on Mac; exited-process alerts do not fire on macOS.
- **Calendar sync is not yet tested against real accounts.** Google,
  Outlook, and Apple sync are built and unit-tested, but live-provider
  testing still needs real accounts.
- **First sync can duplicate events** that already exist both locally
  and remotely without a link. Links and reminder choices are local-only
  and do not transfer through a provider to a fresh library.
- **Exited-process registration failures are silent.** There is not yet
  a failure-status display in Settings.
- **macOS file-watcher quirks.** On macOS, the system file watcher
  sometimes delivers a change event without a filename, and it reports
  activity inside a symlinked folder on the parent watch as activity on
  the link itself. The library scan itself still refuses to follow
  symlinked folders; these are reporting quirks, not followed links.
- **HTML attachment Find counts only.** An HTML attachment's preview
  is a sandboxed frame the app cannot select inside, so Find reports
  match counts without moving to a match. Images have no text to
  search.
- **F3 in PDF, ePub, and DOCX previews only refocuses the reader's
  search box** and does not advance to the next match; advancing
  there uses the reader's own Next or Go-to buttons.
- **Manual validation still owed:** on Windows, JAWS/NVDA/Narrator runs,
  forced-colors rendering, UI Automation smoke runs, Task Scheduler
  reminder delivery, the paste clipboard path, and the reported File
  Explorer invisibility; on Mac, VoiceOver and Zoom validation, the dmg
  install and Gatekeeper flow, and real shortcut behavior.
