# A11y Notebook v1.9.27 — What's new and what changed

This release is built from the 1.9.25 retest: the two template
fixes, six further fixes, Capture Webpage formats, the email-a-note
fix, the dictation microphone shortcut, a fix for webpage
captures that came out empty on script-heavy pages, and a fix for
the built-in templates sometimes failing to copy in on first open.
(The 1.9.26 release was held back when that last failure stopped
its release build; this release carries the same contents plus the
fix.)

## What's new

### Capture a webpage in three formats

- The Capture Webpage dialog now offers three output formats:
  Markdown Note, HTML Note, and Webpage File.
- A Webpage File is the captured page saved as a file in the
  notebook you pick in the dialog. It shows Type "Webpage" in the
  Notes and Files grid, and the grid sorts by Type the same way it
  sorts by Name. A Webpage File always opens read-only in the
  reader.

### Dictation

- Press Alt+Ctrl+D to start dictating into the note you are
  editing. Press it again to stop: what you said is transcribed
  and inserted into the note.
- If the microphone is blocked, an announced dialog says so in
  plain language, explains how to allow it (Windows Settings,
  Privacy & security, Microphone), and offers Retry, which only
  re-runs the microphone request — it does not download the model
  again.
- While you are dictating, F9 mutes and unmutes the microphone
  ("Microphone off." / "Microphone on."). Muting pauses capture
  but keeps the session open; it never ends the session. When you
  are not dictating, F9 does nothing. F8 now toggles the right
  pane.
- A dictation session runs only while you are actively editing
  this note's text field. It ends when you press Alt+Ctrl+D
  again, close the note, leave the text field, switch to reading
  mode, switch to another view, or switch to another note or
  file. If the session ends that way, the partial recording is
  dropped and the app says so plainly.

### Template previews

- The reading view of a template now shows its built-in fields
  filled in as a preview: the template's own title, its notebook,
  and today's date, time, and weekday. Editing mode still shows
  the raw {{title}}, {{notebook}}, and {{date}} markers, and the
  saved text keeps them.

## What changed

### Focus starts in the right place

- The New Note From Template dialog (Ctrl+Shift+N) now starts
  with focus in the Template picker instead of the Note Title
  field.
- The New Task dialog now starts with focus in the "Associate
  with" box instead of the Task Description box.

### Tasks live in Tasks, linked to the item

- A task associated with a note, file, or link now lives in the
  Tasks notebook and only links to the item. Associating a task
  never changes the note, file, or link. The link in Tasks opens
  the item. A task with no association just lives in Tasks.
- Existing checkbox tasks keep working exactly as before; nothing
  is migrated or rewritten.

### The Bookmarks list lands on the bookmark

- Activating a bookmark from the Bookmarks list now moves
  screen-reader focus to the bookmark's exact spot in the note,
  when the note is already open.

### Exported checkboxes work

- Task lines in a note exported to HTML are now real, enabled
  checkboxes in the browser: you can check and uncheck them
  there. The export still cannot write back to the app.

### Webpage captures keep the article text

- Capturing a webpage as an HTML Note or a Webpage File no longer
  drops the whole article on pages with heavy scripts. The part
  that cleans up the page's HTML used to get confused by script
  content and throw everything away; it now keeps the headings,
  paragraphs, and links. Markdown Note captures were never
  affected.

### Emailing a note opens an editable draft

- The email message the app creates for a note now opens as an
  editable draft in your mail app — To, Cc, Subject, and body all
  editable — instead of a read-only received message.

### The built-in templates now copy in reliably

- The first time a library is opened, the five built-in templates
  are copied into its Templates folder. On a slow start that copy
  could fail partway and leave the folder empty; the copy now
  retries a few times, one template at a time, so a single failure
  no longer stops the rest. And a copying failure no longer leaves
  a stale error sitting in the status line.

### Other changes

- A template stays in the "new note from template" picker even
  after its file was replaced by a cloud sync. It used to
  disappear because the picker required a record that syncing
  had dropped.
- Choosing a transcription model can no longer be silently undone
  by a settings save racing it.
- The automated end-to-end tests now number 183, and still run as
  a blocking check in CI and as part of the release workflow.
- The User Guide and the keyboard-shortcuts doc were updated for
  every fix in this release, including F9 for the microphone and
  F8 for the right pane.

## Known limitations

- Mac releases ship unsigned (right-click, then Open, to install; no
  Mac auto-update while unsigned).
- The automated end-to-end tests cannot check screen-reader
  announcements or the virtual-cursor position; manual screen-reader
  testing remains the only check for those.
- Dictation on Mac is unverified: Mac builds are unsigned, with no
  microphone usage description, so microphone access on Mac may not
  work.
- If the library refreshes while you are typing in a template field,
  focus can drop out of the textbox. Your typed values are kept —
  only the focus is lost. (Known follow-up, not fixed in this release.)
- A note created from a template still opens in editing mode; switch
  to reading mode to fill it. Typed field values are kept while the
  note is open, so closing without saving discards them, and any
  content edit drops them. Blank fields keep their {{Name}} markers
  when the values bake in.
- Deleting one occurrence of a recurring appointment is local-only:
  it does not propagate to Google, Outlook, or Apple calendars, so
  the occurrence stays on the provider's calendar. Propagating it
  would need per-provider support for deleted instances.
- A recurring multi-day all-day event only spans multiple days on
  its first occurrence; later recurrences render as a single day.
- The ePub reader's style rules are blocked by the packaged
  security policy, which logs errors when an ePub opens. Section
  text renders and OCR works; the errors are cosmetic. Loosening
  the policy for those rules would weaken it for the whole app, so
  it is left as is for now.
- XFA forms show an honest notice rather than fillable fields:
  pdf.js exposes no XFA fields through its field APIs.
- PDF notes cannot load for a password-protected PDF. Form filling
  itself works on a password-protected PDF, and the filled values
  stay saved in the app — but a filled file cannot be created from
  it, so "Download filled PDF" is unavailable for password-protected
  PDFs.
- Permission-protected PDFs import as read-only: notes and a filled
  file are unavailable, though form filling works in the app and the
  filled values stay saved.
- Alius targets live outside the library, so they are not included
  in a library backup and their contents are not indexed by search:
  only the Alius record's name appears in search results, and
  restoring a backup can produce broken Alius records.
- Bookmark jumps still mismatch on Markdown setext headings and
  blockquoted headings, which the source heading scan cannot see.
- PDF, ePub, and DOCX previews keep their own search boxes; the Find
  match list does not cover them.
- Very large spreadsheets (thousands of rows) may be slow to display;
  the reader caps workbooks at 10,000 rows, 256 columns, and 500,000
  cells, and slide decks at 500 slides. Spreadsheet save preserves the
  file's styles, images, and other parts; ODS cells keep their original
  cell styles. `.xls` reading uses the SheetJS community edition
  (Apache-2.0) — the one format without an in-house reader.
- A permanent delete of a note containing tasks still shows the app's
  existing native permanent-delete confirmation after the task guard.
- The Citations dialog's "Switch to edit mode" button deliberately
  does not move focus while the dialog is open: focus must stay in
  the dialog so a citation can be inserted.
- F3 and Shift+F3 remain intercepted by JAWS in browse mode; use the
  Find match list, or Insert+3 (JAWS pass-through) then F3, to repeat
  a search.
- Items still awaiting a retest verdict: required-fields list,
  unfillable-fields list, password-protected PDF filling, XFA notice,
  notebook silo, import of each format, attach/export/backup,
  screen-reader walk, ePub chapter resume, and ePub annotation
  Jump-to buttons.

## Mac install note

Mac builds are not signed yet. To install, right-click (or Control-click) the .dmg file, then choose Open. In-app updates do not work on Mac while the builds are unsigned — install each new version manually from the releases page.
