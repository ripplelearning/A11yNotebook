# A11y Notebook v1.9.22 — What's new and what changed

Everything in this release was merged since v1.9.21 (November 22, 2026).
It fixes the two failures from the v1.9.21 retest — OCR that would not
run at all, and ePub sections reporting no text — and finishes the
remaining v1.9.21 findings: Markdown bookmark jumps, the Bookmarks
list, Continuous view, the command palette, and reminders for links.
It also adds the full User Guide on F1 and the option to delete a
single occurrence of a recurring appointment.

## What's new

### F1 opens the full User Guide

- Pressing F1 now opens the complete User Guide inside the app,
  instead of only the keyboard shortcuts. The guide is searchable,
  has an interactive table of contents that moves focus to each
  section heading, and includes a Keyboard shortcuts section that is
  generated from the app's own commands when the guide opens — so a
  remapped or added shortcut appears there on its own, with no
  hand-editing. The guide is also in the Help menu. The guide is
  updated with every release, so a feature that ships is documented
  in the same release.

### Delete one occurrence of a recurring appointment

- Deleting a recurring appointment now offers **Delete this
  appointment only** alongside **Delete the whole series**. The
  dialog names the occurrence it would remove, for example "Delete
  only the occurrence on Tuesday, November 24, 2026 at 9:00 AM, or
  delete the whole series?" The deletion stays saved across
  close and reopen.
- Note: deleting one occurrence removes it in A11y Notebook only.
  It does not propagate to Google, Outlook, or Apple calendars,
  so the occurrence stays on the provider's calendar.

### Create a reminder for a link

- The context menu on a link now offers **Create reminder**, like
  the context menu on a note or file. Choosing it opens the new
  reminder dialog with that link already linked to the reminder.

## What changed

### OCR now runs in the installed app

- In v1.9.21, "OCR this file" answered "OCR could not run" in the
  installed app, even though it worked in testing. The cause was
  the production security policy, which only applies to the packaged
  build: it blocked the text-recognition worker, blocked the
  WebAssembly the recognizer needs, and blocked ePub pages, which
  load as temporary browser addresses. The policy now allows those
  three things, and only those three, so OCR runs in the installed
  app exactly as documented: on-device only, whole file, only for
  pages or sections with no extractable text, with progress and
  Cancel, and the language asked each time. A test now guards the
  packaged policy so this cannot silently regress.
- The OCR dialog is now announced properly when it opens: focus
  moves into it and screen readers hear its title and its opening
  message, which used to appear silently. The message itself and
  Escape behavior are unchanged.

### ePub sections render in the installed app

- The same security-policy fix covers the ePub side: ePub sections
  that reported "No extractable text was found in this section" in
  the installed app now render their text. The earlier fixes still
  stand — sections show their real chapter titles, and a book opens
  on its first section with text instead of its cover.

### Markdown bookmark jumps land on the exact line

- Jumping to a bookmark in a Markdown note used to land on the
  heading before the bookmark, or do nothing at all when the
  bookmark was already in that section, and position bookmarks made
  with Ctrl+Alt+B did not jump. Jumps now land on the exact
  bookmarked line, using the same method as jumping to a Find
  match: the line's first words are selected and focus moves
  there, with the heading as a fallback only. Setting a position
  bookmark now records the exact line, and Ctrl+Alt+J jumps to the
  next bookmark after the exact line. PDF bookmarks are unchanged.

### The Bookmarks list stays scoped to the open file

- With a note open, only that note's bookmarks show under the
  Bookmarks heading — including after switching to another view
  (Notes and Files, Tasks, and so on) while the file is still open
  in a tab. Previously the list fell back to the whole library
  whenever no tab was current. With no file open, the library's
  bookmarks still show, so the list remains the way to jump into a
  closed note at its bookmark.

### Continuous view is now a proper choice, not a toggle

- The PDF view control in the PDF Page Navigation section is now a
  radio group, "PDF view", with Paginated view and Continuous view
  — exactly one is always checked, so a screen reader announces
  the current view unambiguously instead of reading one toggle as
  "not pressed". The Previous and Next Page buttons now appear
  only in Paginated view; Continuous view shows the whole PDF as
  one continuous page with no page buttons.

### The command palette dismisses after any command

- Activating any command from the command palette results now
  dismisses the palette and moves focus sensibly into whatever the
  command opened — a dialog, a view, or a setting — instead of
  leaving the palette open and pulling focus back. This applies to
  every command and search, not only Create Reminder. Escape fully
  dismisses the palette.

### Other changes

- The automated end-to-end tests now number 110 (new scenarios for
  the OCR dialog announcement, the packaged security policy, the
  exact-line bookmark jumps, the Bookmarks list scoping, the
  Continuous view radio group, the command palette dismiss, and
  Create Reminder for links), and still run as a blocking check in
  CI and as part of the release workflow.

## Known limitations

- Mac releases ship unsigned (right-click, then Open, to install; no
  Mac auto-update while unsigned).
- The automated end-to-end tests cannot check screen-reader
  announcements or the virtual-cursor position; manual screen-reader
  testing remains the only check for those.
- Deleting one occurrence of a recurring appointment is local-only:
  it does not propagate to Google, Outlook, or Apple calendars, so
  the occurrence stays on the provider's calendar. Propagating it
  would need per-provider support for deleted instances.
- A recurring multi-day all-day event only spans multiple days on
  its first occurrence; later recurrences render as a single day.
- The ePub reader's style rules are blocked by the packaged
  security policy, which logs errors when an ePub opens. Section
  text renders and OCR works; the errors are cosmetic. Loosening
  the policy for those rules would weaken it for the whole app, so
  it is left as is for now.
- XFA forms show an honest notice rather than fillable fields:
  pdf.js exposes no XFA fields through its field APIs.
- PDF notes cannot load for a password-protected PDF. Form filling
  itself works on a password-protected PDF, and the filled values
  stay saved in the app — but a filled file cannot be created from
  it, so "Download filled PDF" is unavailable for password-protected
  PDFs.
- Permission-protected PDFs import as read-only: notes and a filled
  file are unavailable, though form filling works in the app and the
  filled values stay saved.
- Alius targets live outside the library, so they are not included
  in a library backup and their contents are not indexed by search:
  only the Alius record's name appears in search results, and
  restoring a backup can produce broken Alius records.
- Bookmark jumps still mismatch on Markdown setext headings and
  blockquoted headings, which the source heading scan cannot see.
- PDF, ePub, and DOCX previews keep their own search boxes; the Find
  match list does not cover them.
- Very large spreadsheets (thousands of rows) may be slow to display;
  the reader caps workbooks at 10,000 rows, 256 columns, and 500,000
  cells, and slide decks at 500 slides. Spreadsheet save preserves the
  file's styles, images, and other parts; ODS cells keep their original
  cell styles. `.xls` reading uses the SheetJS community edition
  (Apache-2.0) — the one format without an in-house reader.
- A permanent delete of a note containing tasks still shows the app's
  existing native permanent-delete confirmation after the task guard.
- The Citations dialog's "Switch to edit mode" button deliberately
  does not move focus while the dialog is open: focus must stay in
  the dialog so a citation can be inserted.
- F3 and Shift+F3 remain intercepted by JAWS in browse mode; use the
  Find match list, or Insert+3 (JAWS pass-through) then F3, to repeat
  a search.
- Items still awaiting a retest verdict: move-migration link survival,
  import formats, ePub chapter resume, PDF navigation and annotation
  persistence, audio features (real microphone, model download,
  dictation accuracy, playback with a screen reader, mp3/wav import),
  and the library picker.

## Mac install note

Mac builds are not signed yet. To install, right-click (or Control-click) the .dmg file, then choose Open. In-app updates do not work on Mac while the builds are unsigned — install each new version manually from the releases page.
