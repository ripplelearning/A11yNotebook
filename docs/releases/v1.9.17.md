# A11y Notebook v1.9.17 — What's new and what changed

Everything in this release was merged since v1.9.16 (November 16, 2026).
It carries three new features — Alius shortcuts for imported files,
guided paste into a notebook, and fillable PDFs in the reading view —
plus the Mac end-to-end test fix that lets the Mac builds ship:
v1.9.15 and v1.9.16 both shipped Windows-only because the release
workflow's Mac end-to-end tests failed on test-harness gaps, not app
bugs. This release fixes the last of those gaps, so v1.9.17 ships for
both Windows and Mac.

## What's new

### Import now asks: make a copy, or create an Alius

- Every import now asks first: "Make a copy" or "Create an Alius".
  An Alius is a shortcut to the original file: a small `.alius`
  record is stored in the notebook and points at the original file's
  path. The original file stays where it is and is never copied.
  Opening the Alius opens the original in the app's reader or editor,
  and editing it saves back to the original file. "Make a copy"
  behaves exactly as import did before.
- The prompt always asks — there is no "don't ask again" checkbox and
  no setting to remember a default.
- An Alius shows in Notes and Files with Type "Alius", and its
  properties show the target path. Any file can be an Alius target
  except executables, scripts, and shortcuts.
- If the target has moved, been renamed, or been deleted, the Alius
  shows as broken in the grid, with "Locate the file" and "Remove
  the Alius" actions. The Alius record syncs with the library, so on
  another computer where the target is missing it shows as broken
  there too, with a retarget action.
- If the target was edited outside the app while it is open in the
  app, saving is refused and the app shows "The original changed
  outside the app" with Reload and Save anyway choices, so an outside
  edit is never silently overwritten.
- An Alius is allowed inside a whole-library-encrypted library, with
  a warning that the target file itself is not encrypted.

### Paste whole files and structured content into a notebook

- Pasting into a notebook (with no note open) now starts a guided
  flow. It asks whether to store the pasted content as a new note or
  as a file attachment, what format to store it as, and what the file
  name should be.
- A whole file keeps its own format: it only asks copy vs Alius and
  the file name. Pasted files get the same validation as imports, so
  an unsupported or oversized file is refused with a clear reason.
- Pasted text can be stored as Markdown, rich text (an HTML note,
  edited with the rich text editor), or plain text. Structured
  content pasted as Markdown converts headings, lists, and tables to
  Markdown and drops anything with no Markdown equivalent.
- Images inside pasted HTML stay inline in the HTML note when they
  are data-URL images. A pasted picture (for example a screenshot)
  becomes a copied picture that keeps its caption and alt text when
  the source provides them.
- The default file name is the source file's name for whole files,
  and the first line for text. Name collisions keep the existing
  "(imported)" suffix.
- Pasting with no notebook selected now asks which notebook to use,
  with the current notebook offered first, instead of refusing.

### Fillable PDFs can now be filled in the reading view

- A fillable PDF's fields now appear inline in the reflowed reading
  view, in reading order, with their labels — fill in the fields as
  you read. Text fields, checkboxes, radio groups, and dropdowns are
  fillable, the same field types FRAME PDF Studio supports.
- Filled values are stored in the app, like PDF notes, and are
  visible only inside A11y Notebook. A "Download filled PDF" action
  on the form exports a real filled PDF when you want one.
- A password-protected PDF asks for its password once per session
  and keeps it only in memory; filling works, and the filled values
  stay saved in the app.
- Filling an Alius never touches the original file: saving a filled
  copy always creates a new file in the library.
- Required fields that are still empty are listed with a "Go to"
  button for each one, and fields the app cannot fill are listed
  with the reason.
- XFA forms were attempted, not refused — but pdf.js exposes no XFA
  fields through its field APIs, so an XFA form shows an honest
  notice ("This form uses XFA and no fields could be loaded in the
  app.") rather than fillable fields. Dynamic XFA features do not
  work in the app.

## What changed

- The end-to-end tests now resolve the macOS temporary directory
  through its real path before checking import fixtures. On macOS the
  temp directory path traverses the `/var` to `/private/var` symlink,
  and the app's no-symlinks check rejected the test fixtures. This is
  a test-only change; the app itself is unchanged by it. It fixes the
  last two Mac end-to-end failures from v1.9.16, so the Mac builds
  ship in this release.
- The automated end-to-end tests now number 27 (12 new scenarios:
  8 paste scenarios and 4 fillable-PDF scenarios), and still run as
  a blocking check in CI and as part of the release workflow.

## Known limitations

- The Citations dialog's "Switch to edit mode" button deliberately
  does not move focus while the dialog is open: focus must stay in
  the dialog so a citation can be inserted.
- F3 and Shift+F3 remain intercepted by JAWS in browse mode; use the
  Find match list, or Insert+3 (JAWS pass-through) then F3, to repeat
  a search.
- Mac releases ship unsigned (right-click, then Open, to install; no
  Mac auto-update while unsigned).
- PDF, ePub, and DOCX previews keep their own search boxes; the Find
  match list does not cover them.
- Very large spreadsheets (thousands of rows) may be slow to display;
  the reader caps workbooks at 10,000 rows, 256 columns, and 500,000
  cells, and slide decks at 500 slides. Spreadsheet save preserves the
  file's styles, images, and other parts; ODS cells keep their original
  cell styles. `.xls` reading uses the SheetJS community edition
  (Apache-2.0) — the one format without an in-house reader.
- A permanent delete of a note containing tasks still shows the app's
  existing native permanent-delete confirmation after the task guard.
- The automated end-to-end tests cannot check screen-reader
  announcements or the virtual-cursor position; manual screen-reader
  testing remains the only check for those.
- XFA forms show an honest notice rather than fillable fields (see
  above): pdf.js exposes no XFA fields through its field APIs.
- PDF notes cannot load for a password-protected PDF. Form filling
  itself works on a password-protected PDF, and the filled values
  stay saved in the app — but a filled file cannot be created from
  it, so "Download filled PDF" is unavailable for password-protected
  PDFs.
- Alius targets live outside the library, so they are not included
  in a library backup and their contents are not indexed by search:
  only the Alius record's name appears in search results, and
  restoring a backup can produce broken Alius records.
- Items still awaiting a retest verdict: move-migration link survival,
  import formats, ePub chapter resume, PDF navigation and annotation
  persistence, audio features (real microphone, model download,
  dictation accuracy, playback with a screen reader, mp3/wav import),
  and the library picker.

## Mac install note

Mac builds are not signed yet. To install, right-click (or Control-click) the .dmg file, then choose Open. In-app updates do not work on Mac while the builds are unsigned — install each new version manually from the releases page.
