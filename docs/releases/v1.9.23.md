# A11y Notebook v1.9.23 — What's new and what changed

Everything in this release was merged since v1.9.22 (November 23, 2026).
It adds Save As Template, a Templates folder in every library, and
fillable {{Name}} textboxes in templates, and fixes a save that could
be silently dropped while a disk check was running. It also fixes the
nine items from the 1.9.22 retest listed below.

## What's new

### Save any note as a template

- With a note open, Save As Template (Ctrl+Shift+S) opens a dialog
  asking for the template name, prefilled with the note's title, and
  whether to copy the note into the Templates folder or create the
  template and discard the original note. If a template with that
  name already exists in the Templates folder, the dialog asks
  whether to replace it. The template keeps the note's format.

### A Templates folder in every library

- Every library gets a Templates folder holding all templates,
  including the five built-in templates — Daily, Meeting, Project,
  Reading, Lecture — copied in as editable notes. Existing libraries
  get them the first time they are opened after this update, and
  seeding happens once, so a deleted built-in stays deleted. The
  Templates folder shows as a notebook, and template notes open in
  reading mode like any other note; editing mode is for changing
  the template.

### Fillable {{Name}} textboxes in templates

- Write {{Name}} in a template — for example {{Client Name}} — and
  it renders as a textbox with that name as its accessible name,
  filled in from read-only mode while the rest of the note stays
  read-only, the same way fillable PDFs fill in place. The six
  placeholders that already fill themselves in ({{title}},
  {{notebook}}, {{date}}, {{time}}, {{weekday}}, {{cursor}}) keep
  doing that; any other {{Name}} becomes a fillable textbox.
  Textboxes only for now.
- Saving bakes the values into the note text, so the filled note is
  plain filled-in text — searchable, exportable, printable — and
  the note keeps a link to its template, with a button in its
  read-only view ("New fillable copy from this template") for a
  fresh fillable copy. The link follows renames and moves, and
  says the template is gone if it is deleted.
- Filling a template itself offers a filled copy instead of
  changing the template, and saving that copy asks for the format,
  where to save it, and the name to use.
- Duplicate field names stay independent and get numbered
  accessible names, like "Client Name 1" and "Client Name 2".

## What changed

### A manual save can no longer be dropped

- A manual save could silently return while a disk check was
  running, so the save could be dropped. The save path now waits
  for the disk check to finish first.

### Fixes from the 1.9.22 retest

- The User Guide is rewritten in plain, friendly language for the
  average user, and restructured: first an Introduction to A11y
  Notebook, its features, capabilities, and common uses; then the
  user interface and how to navigate it using a keyboard; then the
  accessibility features and accessibility settings and how to
  access them. The Keyboard Shortcuts section no longer shows a
  visible HTML comment.
- All date fields now use MM/DD/YYYY: the Due Date and Reminder Date
  fields in the New Task dialog and the Date field in the Create
  Reminder dialog, including their labels and error messages. The
  User Guide Tasks section no longer gives dates as YYYY-MM-DD.
- The Link to box in the Create Reminder dialog now offers a Link
  option, so a reminder can be linked to a link as well as to a
  note or a file.
- In an ePub, activating a Jump to annotation button now moves your
  focus to the spot in the book where the annotation was inserted,
  even when it is in another section.
- When a file or note is open, the title bar now reads "[FileName] |
  [NotebookName] | [LibraryName] | A11y Notebook". A file at the
  library root has no notebook, so that part is left out; with no
  file open, the view title is unchanged.
- In Continuous view, every page now starts with a "Page N" heading
  under the "Page text" heading, so navigating by heading with a
  screen reader moves through each heading and page of the PDF in
  order.
- Jumping to a bookmark in a Markdown note now moves programmatic
  focus and the virtual cursor to the exact bookmarked location, in
  reading mode and in editing mode — not to the heading before it —
  whether you jump with Ctrl+Alt+J or activate the bookmark from the
  Bookmarks list. The cause was twofold: opening the naming dialog
  collapsed the document selection, so a second bookmark stored
  offset 0, and a stale bookmarks fetch racing a save overwrote the
  saved bookmark. Ctrl+Alt+J jumps to the next bookmark; it no
  longer sets one.
- From the Notes and Files grid, the context menu on a selected
  note, link, or file now offers Create Task, opening the New Task
  dialog with the selected item linked to the task.
- Pressing Escape in search now clears the search text and removes
  the search results from the display.

### Other changes

- The automated end-to-end tests now number 135 (8 new scenarios
  for Save As Template and fillable template fields, and 17 more for
  the 1.9.22 retest fixes), and still run as a blocking check in CI
  and as part of the release workflow.
- The User Guide and the keyboard-shortcuts doc were updated for
  templates and for every fix in this release.

## Known limitations

- Mac releases ship unsigned (right-click, then Open, to install; no
  Mac auto-update while unsigned).
- The automated end-to-end tests cannot check screen-reader
  announcements or the virtual-cursor position; manual screen-reader
  testing remains the only check for those.
- If the library refreshes while you are typing in a template field,
  focus can drop out of the textbox. Your typed values are kept —
  only the focus is lost. (Known follow-up, not fixed in this release.)
- A note created from a template still opens in editing mode; switch
  to reading mode to fill it. Typed field values are kept while the
  note is open, so closing without saving discards them, and any
  content edit drops them. Blank fields keep their {{Name}} markers
  when the values bake in.
- Deleting one occurrence of a recurring appointment is local-only:
  it does not propagate to Google, Outlook, or Apple calendars, so
  the occurrence stays on the provider's calendar. Propagating it
  would need per-provider support for deleted instances.
- A recurring multi-day all-day event only spans multiple days on
  its first occurrence; later recurrences render as a single day.
- The ePub reader's style rules are blocked by the packaged
  security policy, which logs errors when an ePub opens. Section
  text renders and OCR works; the errors are cosmetic. Loosening
  the policy for those rules would weaken it for the whole app, so
  it is left as is for now.
- XFA forms show an honest notice rather than fillable fields:
  pdf.js exposes no XFA fields through its field APIs.
- PDF notes cannot load for a password-protected PDF. Form filling
  itself works on a password-protected PDF, and the filled values
  stay saved in the app — but a filled file cannot be created from
  it, so "Download filled PDF" is unavailable for password-protected
  PDFs.
- Permission-protected PDFs import as read-only: notes and a filled
  file are unavailable, though form filling works in the app and the
  filled values stay saved.
- Alius targets live outside the library, so they are not included
  in a library backup and their contents are not indexed by search:
  only the Alius record's name appears in search results, and
  restoring a backup can produce broken Alius records.
- Bookmark jumps still mismatch on Markdown setext headings and
  blockquoted headings, which the source heading scan cannot see.
- PDF, ePub, and DOCX previews keep their own search boxes; the Find
  match list does not cover them.
- Very large spreadsheets (thousands of rows) may be slow to display;
  the reader caps workbooks at 10,000 rows, 256 columns, and 500,000
  cells, and slide decks at 500 slides. Spreadsheet save preserves the
  file's styles, images, and other parts; ODS cells keep their original
  cell styles. `.xls` reading uses the SheetJS community edition
  (Apache-2.0) — the one format without an in-house reader.
- A permanent delete of a note containing tasks still shows the app's
  existing native permanent-delete confirmation after the task guard.
- The Citations dialog's "Switch to edit mode" button deliberately
  does not move focus while the dialog is open: focus must stay in
  the dialog so a citation can be inserted.
- F3 and Shift+F3 remain intercepted by JAWS in browse mode; use the
  Find match list, or Insert+3 (JAWS pass-through) then F3, to repeat
  a search.
- Items still awaiting a retest verdict: move-migration link survival,
  import formats, ePub chapter resume, PDF navigation and annotation
  persistence, audio features (real microphone, model download,
  dictation accuracy, playback with a screen reader, mp3/wav import),
  and the library picker.

## Mac install note

Mac builds are not signed yet. To install, right-click (or Control-click) the .dmg file, then choose Open. In-app updates do not work on Mac while the builds are unsigned — install each new version manually from the releases page.
