# A11y Notebook v1.9.18 — What's new and what changed

Everything in this release was merged since v1.9.17 (November 16, 2026).
It is a fixes release: the startup-tutorial trap, all eight fixes from
the v1.9.17 retest, two follow-up gaps found while fixing those, and the
Insert link button, which silently did nothing. No new features, and
nothing in it changes how existing features work except where noted.

## What's new

### Insert link works in the rich-text editor

- The Insert link button in the rich-text editor used to ask for the
  address with a native prompt that Electron does not implement, so
  the button silently did nothing. It now asks in the app's own
  accessible dialog, with a Link address field and a Link text field.
- The address must be an http, https, or mailto URL, the same rule
  the Markdown editor's Insert link dialog already used; anything
  else is refused with a clear reason instead of inserting a link
  that goes nowhere.
- The selected text becomes the link text. With nothing selected, the
  address itself becomes the link text. The link lands as Markdown
  link syntax in a Markdown note and as an anchor in an HTML note.
- The same fix covers the other ways into Insert link while editing
  rich text: the context menu and Ctrl+K now open the dialog too.

### Pictures can be pasted and inserted into Markdown notes

- Pasting a picture into a Markdown note used to drop it, and the
  Insert image toolbar did nothing there either. Both now insert the
  picture inline, keeping its description (alt text, or its figure's
  caption) when the source provides one.
- Inserting an image into an HTML note from the toolbar works too:
  it used the same dead native prompt, and now asks in the app's own
  accessible dialog, with the description required.

### Nothing opens automatically after an import or a paste

- Imported files (a copy or an Alius) and pasted content no longer
  open on their own; they wait until you open them.
- Pasting a folder as a library adds it to Libraries without
  switching to it or opening it. The same goes for the "document
  changed" message that used to follow a copy import: the import's
  own file-watcher event no longer triggers it, while a genuine
  change on disk still warns.

## What changed

### Startup tutorial: Help menu Tutorial and What's New

- Checking "Don't show this again" on the startup tutorial used to
  leave no way back to the tutorial or to What's New. Help now has a
  Tutorial entry that re-opens the full tour any time, and a What's
  New entry that shows only the last page — what's new in the
  currently installed version.
- The checkbox is relabelled "Show the tutorial after each update":
  checked means the tutorial shows after updates, unchecked means it
  does not. The choice persists and controls the auto-show.

### Fixes from the v1.9.17 retest

- An Alius Word document now opens in the app. The annotations check
  looked at the `.alius` record's name instead of the original file,
  so opening failed with a "DOCX annotations require a Word
  document" error. The check now resolves the record to its target.
- Download filled PDF no longer fails on rich-text fields. One empty
  rich-text field used to abort the whole download; the export now
  reads the field's plain-text value, and a field it cannot write is
  listed instead of failing the export.
- ePub books open again. The reader repairs a damaged package
  in-memory before opening it — missing entries, missing navigation,
  and non-HTML spine items no longer fail the whole book. Well-formed
  books pass through unchanged, and the file on disk is untouched.
- Bookmark jumps now work in Markdown notes whose headings contain
  wiki links or images: the heading text is normalised the same way
  the reading view renders it, so the jump lands on the heading
  instead of the top of the note.
- The "Install on Exit" update option is removed. It set its flag
  after the download had finished, but the updater only reads that
  flag while a download is running, so the button silently did
  nothing. Making it work would install every update on quit without
  asking, so the downloaded state now offers Restart and install or
  Close.
- The paste dialog now starts focus on the New note versus File
  attachment choice instead of the file name box.
- Pasted pictures keep their description: the alt text first, then
  the enclosing figure's caption when there is no alt text. Pasting
  an image into an open HTML note now inserts it inline with its
  description.

### Other changes

- The automated end-to-end tests now number 69 (5 new Insert link
  scenarios), and still run as a blocking check in CI and as part of
  the release workflow.

## Known limitations

- Mac releases ship unsigned (right-click, then Open, to install; no
  Mac auto-update while unsigned).
- The automated end-to-end tests cannot check screen-reader
  announcements or the virtual-cursor position; manual screen-reader
  testing remains the only check for those.
- XFA forms show an honest notice rather than fillable fields:
  pdf.js exposes no XFA fields through its field APIs.
- PDF notes cannot load for a password-protected PDF. Form filling
  itself works on a password-protected PDF, and the filled values
  stay saved in the app — but a filled file cannot be created from
  it, so "Download filled PDF" is unavailable for password-protected
  PDFs.
- Alius targets live outside the library, so they are not included
  in a library backup and their contents are not indexed by search:
  only the Alius record's name appears in search results, and
  restoring a backup can produce broken Alius records.
- Bookmark jumps still mismatch on Markdown headings containing raw
  HTML.
- PDF, ePub, and DOCX previews keep their own search boxes; the Find
  match list does not cover them.
- Very large spreadsheets (thousands of rows) may be slow to display;
  the reader caps workbooks at 10,000 rows, 256 columns, and 500,000
  cells, and slide decks at 500 slides. Spreadsheet save preserves the
  file's styles, images, and other parts; ODS cells keep their original
  cell styles. `.xls` reading uses the SheetJS community edition
  (Apache-2.0) — the one format without an in-house reader.
- A permanent delete of a note containing tasks still shows the app's
  existing native permanent-delete confirmation after the task guard.
- The Citations dialog's "Switch to edit mode" button deliberately
  does not move focus while the dialog is open: focus must stay in
  the dialog so a citation can be inserted.
- F3 and Shift+F3 remain intercepted by JAWS in browse mode; use the
  Find match list, or Insert+3 (JAWS pass-through) then F3, to repeat
  a search.
- Items still awaiting a retest verdict: move-migration link survival,
  import formats, ePub chapter resume, PDF navigation and annotation
  persistence, audio features (real microphone, model download,
  dictation accuracy, playback with a screen reader, mp3/wav import),
  and the library picker.

## Mac install note

Mac builds are not signed yet. To install, right-click (or Control-click) the .dmg file, then choose Open. In-app updates do not work on Mac while the builds are unsigned — install each new version manually from the releases page.
