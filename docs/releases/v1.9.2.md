# A11y Notebook v1.9.2 — What's new and what changed

Everything in this release was merged since v1.9.1 (October 27, 2026).
This is a small fixes release; v2.0 remains the intended public release.

## What changed

- **Focus on open.** Opening the app now focuses the selected tab, so
  a screen reader announces one element ("Welcome, tab selected")
  instead of reading the whole window. This addresses the 1.9.1
  regression where JAWS treated the window as a web page on open,
  announced the headings and landmarks summary, and read the entire
  window top to bottom. The focus move runs once, only while focus is
  still on the body and no dialog is open, so it never steals focus
  from a dialog, a click, or a later focus request. The main-landmark
  change from 1.9.1 is unchanged: JAWS Q still jumps to the document.

## Fixes in this release

- Settings validation no longer fails the whole file over a shortcut
  saved for a command that was later removed or renamed. Unknown
  command ids are now dropped and the surviving settings load; a
  non-string binding for a surviving command still fails, since that
  indicates a damaged file rather than staleness.
- Settings load failures now name the exact failing check (for
  example, an invalid shortcut, invalid values, or a shortcut
  conflict) instead of only the failure class, so the next report
  identifies what to fix.

## Known limitations

- **The initial-focus change still needs a screen-reader run to
  confirm.** Automated tests cover the focus behavior, but only a
  JAWS run on open can confirm the whole-window reading has stopped.
- **Settings load failures still need their underlying cause fixed.**
  This release reports the specific failure and protects the stored
  file, and drops stale command shortcuts, but a settings file that
  fails on a value will keep failing to load until that value is
  repaired or the file is regenerated.
- **Unsigned builds.** Windows may show SmartScreen warnings and macOS
  may show Gatekeeper warnings (install via right-click → Open). There
  is no code-signing certificate yet, and no Apple Developer account for
  Mac signing and notarization.
- **Mac icon.** The Mac icon was generated from the Windows icon's
  256px image (the largest source available), so large icons render
  soft until a higher-resolution source exists.
- **Mac in-app updates do not run while unsigned.** Mac users download
  new versions from the release page.
- **Background reminders are Windows-only.** The setting is labeled as
  such on Mac; exited-process alerts do not fire on macOS.
- **Calendar sync is not yet tested against real accounts.** Google,
  Outlook, and Apple sync are built and unit-tested, but live-provider
  testing still needs real accounts.
- **First sync can duplicate events** that already exist both locally
  and remotely without a link. Links and reminder choices are local-only
  and do not transfer through a provider to a fresh library.
- **Exited-process registration failures are silent.** There is not yet
  a failure-status display in Settings.
- **macOS file-watcher quirks.** On macOS, the system file watcher
  sometimes delivers a change event without a filename, and it reports
  activity inside a symlinked folder on the parent watch as activity on
  the link itself. The library scan itself still refuses to follow
  symlinked folders; these are reporting quirks, not followed links.
- **Manual validation still owed:** on Windows, JAWS/NVDA/Narrator runs,
  forced-colors rendering, UI Automation smoke runs, Task Scheduler
  reminder delivery, the paste clipboard path, and the reported File
  Explorer invisibility; on Mac, VoiceOver and Zoom validation, the dmg
  install and Gatekeeper flow, and real shortcut behavior.
